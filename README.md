# Многошаговое планирование поверх FB-представлений

Моё решение тестового задания по статье *Switching Successor Measures for
Hierarchical Zero-shot Reinforcement Learning*. Задача — придумать
high-level механизм, который рассуждает не об одном шаге вперёд, а о
последовательности шагов, и сравнить его с готовым жадным бейзлайном на
`antmaze-medium-navigate-v0`.

Полная история экспериментов (что пробовали, что не сработало и почему) —
в [`REPORT.md`](REPORT.md). Здесь — только суть и как всё запустить.

## Идея решения одной строкой

Жадный бейзлайн выбирает лучший следующий шаг по одной формуле из статьи
(switching advantage) и ни разу не заглядывает дальше. В финальном
решении я строю граф из реально пройденных переходов в датасете — это
даёт маршрут, который честно обходит стены лабиринта, — а формулу из
статьи использую только для выбора лучшего варианта среди уже
гарантированно достижимых точек. Перед этим я испробовал ещё десять
разных идей — все они и почему не сработали разобраны в `REPORT.md`.

## Итоговый результат

| Метод | Success rate | Доверительный интервал (95%) |
|---|---|---|
| Готовый бейзлайн (жадный, single-intention) | 0.670 | [0.578, 0.762] |
| **Мой метод (граф + FB)** | **0.520** | **[0.422, 0.618]** |

Метод в среднем уступает бейзлайну, но на одной из пяти задач среды
(там, где путь до цели самый запутанный) он его обгоняет — 0.85 против
0.70. Подробный разбор по каждой задаче — в `REPORT.md`.

## Соответствие условиям задания

- Использую только F, B, π_l и офлайн-датасет — никакой карты стен
  или другой скрытой от агента информации о лабиринте.
- Граф я строю из реальных переходов датасета — это справочная таблица,
  а не генеративная модель, ничего не выдумывает.
- Никакого нового взаимодействия со средой для обучения — граф и все
  расчёты я делаю офлайн.
- F, B и π_l я не переобучал — использовал ровно в том виде, в каком
  выданы в чекпоинте.

## Как запустить

**Важно про версию Python.** Требуется **Python 3.12** — именно эту
версию я использовал при разработке и тестировании решения. Причина:
у зависимости `labmaze` (используется `ogbench`/mujoco) на PyPI на
момент написания **нет готовых бинарных пакетов под Python 3.13** ни для
одной операционной системы — только под 3.11 и 3.12. Без готового пакета
pip пытается собрать `labmaze` из исходников, для чего нужен `bazel`
(специальная система сборки), которого обычно нет и ставить который ради
этого не стоит. Python 3.11, по всей видимости, тоже подошёл бы (для
него тоже есть готовые пакеты `labmaze`), но я лично не тестировал —
если используете 3.11 и что-то пойдёт не так, попробуйте именно 3.12.

Проверьте, есть ли у вас Python 3.12:
```bash
python3.12 --version
```

**Если команда не найдена** — установите его:

- **macOS** (через Homebrew — если Homebrew не установлен, сначала
  `/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"`):
  ```bash
  brew install python@3.12
  ```
- **Linux (Ubuntu/Debian)**:
  ```bash
  sudo apt update && sudo apt install python3.12 python3.12-venv
  ```
- **Windows** — скачать инсталлятор Python 3.12 с [python.org](https://www.python.org/downloads/release/python-3120/)
  и при установке отметить «Add python.exe to PATH».

**На Windows команда `python3.12` обычно не работает** (в отличие от
macOS/Linux) — там нет такого имени команды. Вместо неё используйте:
```
python --version
```
Если это уже покажет `Python 3.12.x` — просто используйте `python` вместо
`python3.12` во всех командах ниже. Если на компьютере несколько версий
Python сразу, воспользуйтесь **py launcher** (ставится вместе с
официальным установщиком):
```
py --list          # покажет все установленные версии
py -3.12 -m venv venv
```

Дальше — установка окружения и зависимостей:

```bash
python -m venv venv               # или: py -3.12 -m venv venv
venv\Scripts\activate              # Windows (cmd/PowerShell)
# source venv/bin/activate         # macOS/Linux
python -m pip install --upgrade pip
python -m pip install "jax>=0.4.38" "flax>=0.10.2" "distrax>=0.1.5" "gymnasium==0.29.1" "ml_collections>=1.1.0" "ogbench==1.1.4" "h5py==3.12.1" "wandb>=0.19.11" numpy
```

**PowerShell и `Set-ExecutionPolicy`.** Если при `venv\Scripts\activate`
PowerShell выдаёт ошибку про «execution policy» — выполните один раз:
```
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
и повторите активацию.

**Если на этом шаге всё же видите `Building wheel for labmaze` и ошибку
про `bazel`** — значит, venv создался не от Python 3.12. Проверьте
версию прямо внутри активированного окружения (`python --version`) — она
должна показывать `3.12.x`. Если нет, пересоздайте venv явно от
нужной версии: `python3.12 -m venv venv` (macOS/Linux) или
`py -3.12 -m venv venv` (Windows).

Переименовать чекпоинт (если ещё не переименован):
```bash
mv checkpoints/params.pkl checkpoints/params_1000000.pkl
```

Запуск:
```bash
python3 run_compare_eval.py     # оба метода сразу, ~25-35 минут, все 5 задач
```

Датасет OGBench скачается автоматически при первом запуске. Каждая
задача оценивается на 20 сидах, всего 100 испытаний на метод.

## Ограничения

- Я проверил метод только на `antmaze-medium-navigate-v0`; более сложные
  варианты среды (teleport/large/giant) не тестировал из-за нехватки
  времени.
- При повторных запусках одних и тех же сидов результат отдельного
  эпизода иногда чуть отличается (вероятно, из-за многопоточных
  вычислений с плавающей точкой) — поэтому все итоговые цифры я считаю
  по большому числу независимых испытаний, а не по одному прогону.
